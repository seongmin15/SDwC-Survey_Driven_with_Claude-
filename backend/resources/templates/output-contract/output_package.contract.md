## Document Numbering

| Range | Service Type | Documents |
|-------|-------------|-----------|
| 00-09 | common | Project profile, collaboration, opportunity, mvp, requirements, architecture, git, decisions, deployment, observability, backlog |
| 10-19 | common (conditional) | Deployment templates: docker-compose (10), k8s (11), etc. Generated based on `deployment.initial` value |
| 20-24 | backend_api | API contract, data design, verification (contract, integration, security) |
| 30-33 | web_ui | User flow, verification (e2e, accessibility, visual) |
| 40-43 | worker | Worker design, data flow, verification (reliability, performance) |
| 50-53 | mobile_app | App design, data/state, verification (e2e, platform) |
| 60-63 | data_pipeline | Pipeline design, data schema, verification (quality, performance) |
| 999 | common | Roadmap & extensions |

## Validation Rules

### Substitution

- All `{{...}}` variables must be substituted (0 remaining).
- `<!-- AI: -->` comments must be preserved.
- All AI comments must use timing prefix: `<!-- AI:INIT: -->` or `<!-- AI:ONGOING: -->`. No unprefixed `<!-- AI: -->` allowed.
- Conditional blocks (`{{#if}}`, `{{#each}}`) must be correctly evaluated.
- No empty sections.

### Multi-DB

- `{{#each backend.databases}}` blocks must iterate over all DB entries.
- Each DB entry must have `db.engine`, `db.role`, `db.reason`.
- Empty `backend.databases` (min_items: 0) is valid and means no DB.

### Branch Strategy

- CLAUDE.md must contain only the sections matching the selected `git.branch_strategy`.
- Post-Task Completion must reference the correct integration branch.
- Project Initialization must use the correct init sequence.

### MSA-Specific

- `docs/services/` must contain a directory for every service in `service_list`.
- Each service directory must contain documents matching its type.
- Per-service variables must be correctly mapped (see generation_rules.md §3.4).
